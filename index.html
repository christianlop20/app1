Control de Versiones

Definición

El control de versiones (VCS, por sus siglas en inglés) es un sistema que registra los cambios realizados sobre un archivo o conjunto de archivos a lo largo del tiempo, permitiendo recuperar versiones específicas, comparar modificaciones, revertir errores y colaborar de forma ordenada en equipo sin sobrescribir el trabajo de otros desarrolladores.

¿Cuáles son? (Tipos de sistemas de control de versiones)

1. Locales (LVCS)

Almacenan las revisiones de archivos en una base de datos local dentro de la misma computadora del usuario (mediante parches o diferencias entre versiones). Ejemplo: RCS (Revision Control System).

2. Centralizados (CVCS)

Utilizan un único servidor central que contiene todos los archivos versionados y varios clientes que descargan copias de trabajo desde ese servidor. Ejemplos: Subversion (SVN), CVS, Perforce.

3. Distribuidos (DVCS)

Cada desarrollador clona una copia completa del repositorio, incluyendo todo su historial. Esto permite trabajar sin conexión y tener múltiples respaldos completos. Ejemplos: Git, Mercurial.

Características, Ventajas y Desventajas

Tipo Características Ventajas Desventajas
Local (LVCS) Historial guardado localmente mediante conjuntos de parches. Rápido, simple, no requiere red ni servidor externo. Imposible colaborar en equipo; si falla el disco local se pierde todo el historial.
Centralizado (CVCS) Un servidor central único gestiona permisos y versiones. Control administrativo centralizado; fácil de entender qué hace cada miembro. Punto único de fallo (si cae el servidor, nadie puede guardar cambios ni ver historial).
Distribuido (DVCS) Repositorios completos en cada cliente; ramificación y fusión avanzadas. Trabajo offline, alta velocidad, redundancia total, flujo flexible por ramas. Curva de aprendizaje inicial más alta; mayor uso de espacio local en proyectos muy pesados.

Funcionamiento

En sistemas modernos como Git, el flujo de trabajo se organiza en tres estados principales:

  • Directorio de trabajo (Working Directory): Carpeta donde se editan los archivos actuales.
  • Área de preparación (Staging Area / Index): Zona intermedia donde se seleccionan los cambios exactos que formarán parte de la siguiente instantánea.
  • Repositorio (.git): Base de datos donde se almacenan permanentemente las instantáneas (commits) identificadas mediante un hash criptográfico SHA-1/SHA-256.

Rastreo y Gestión de Cambios

El control de versiones rastrea quién modificó cada línea, cuándo lo hizo y por qué (mediante mensajes de confirmación). Para gestionar cambios en paralelo se utilizan ramas (branches) independientes (por ejemplo, main para producción, develop para integración y feature/login para nuevas funciones), que posteriormente se integran mediante operaciones de fusión (merge) o reorganización (rebase), resolviendo conflictos de manera controlada.

Ejemplos Prácticos

# Inicializar repositorio, preparar cambios y guardar versión
git init
git add index.html css/styles.css
git commit -m "feat: estructura inicial del tutorial responsivo"

# Crear una rama para una nueva funcionalidad y fusionarla
git checkout -b feature/buscador
git commit -am "feat: filtro de búsqueda en tiempo real"
git checkout main
git merge feature/buscador

Persistencia y Acceso a Datos

Definición

La persistencia de datos es la capacidad de una aplicación móvil para conservar información más allá del ciclo de vida de ejecución del proceso o del cierre de la aplicación, permitiendo recuperarla, consultarla y actualizarla posteriormente.

Características

  • Durabilidad: Los datos permanecen almacenados aunque el dispositivo se reinicie o la app se cierre.
  • Integridad y consistencia: Garantiza que la información no se corrompa durante lecturas o escrituras concurrentes.
  • Seguridad y privacidad: Aislamiento mediante sandboxing por aplicación y cifrado de datos sensibles.
  • Rendimiento: Acceso rápido acorde a las limitaciones de memoria y batería de dispositivos móviles.

Formas de Persistencia en Dispositivos Móviles

1. Archivos

Almacenamiento directo en el sistema de archivos interno (privado de la app) o externo (compartido). Ideal para documentos, imágenes, configuraciones JSON/XML o caché binaria. Incluye almacenamientos clave-valor ligeros como SharedPreferences / DataStore (Android) o UserDefaults (iOS).

2. Bases de Datos Locales

Motores embebidos dentro del dispositivo que permiten consultas estructuradas, índices y transacciones ACID sin conexión a internet. Ejemplos: SQLite, Realm, ObjectBox.

3. Bases de Datos Remotas (Servicios Web)

Almacenamiento centralizado en servidores en la nube accesibles mediante APIs REST o GraphQL sobre HTTP/HTTPS. Permite sincronización multi-dispositivo y respaldo en tiempo real (ej. Firebase Firestore, PostgreSQL vía API).

Tipos de Datos Almacenables según la Forma de Persistencia

  • Preferencias / Clave-Valor: Tipos primitivos (booleanos, enteros, cadenas, flotantes) para configuraciones de usuario (tema oscuro, idioma).
  • Archivos planos y binarios: Texto (TXT, JSON, CSV), multimedia (PNG, MP4, MP3), PDF y cachés offline.
  • Bases de datos locales: Registros relacionales estructurados, catálogos offline, historial de transacciones y colas de sincronización.
  • Bases de datos remotas: Perfiles de usuario, datos compartidos entre usuarios, analíticas globales e inventario en tiempo real.

Mecanismos de Control de Acceso a Medios Persistentes

  • Biblioteca de clases (APIs nativas de E/S): Clases estándar del SDK para abrir flujos de bytes/caracteres, gestionar permisos y leer/escribir archivos (ej. java.io, java.nio, FileManager en Swift).
  • Clases de SQLite: Interfaces de bajo nivel como SQLiteOpenHelper y SQLiteDatabase (Android) o la librería C sqlite3 (iOS) que ejecutan sentencias SQL directamente y devuelven cursores.
  • Mapeo Relacional de Objetos (ORM): Capa de abstracción que convierte tablas de bases de datos en objetos del lenguaje de programación, evitando SQL repetitivo y validando consultas en tiempo de compilación. Ejemplos: Room (Android), Core Data / SwiftData (iOS).

Proceso de Autenticación y Consumo de Servicios Web

  1. Solicitud de credenciales: El usuario envía credenciales (usuario/contraseña o proveedor OAuth2/OpenID Connect) por HTTPS.
  2. Emisión de Token: El servidor valida y devuelve un token de acceso (como JWT - JSON Web Token) y un Refresh Token.
  3. Almacenamiento seguro: La app guarda el token en almacenamiento cifrado (EncryptedSharedPreferences / Android Keystore o iOS Keychain).
  4. Consumo de API: Cada petición HTTP incluye el encabezado Authorization: Bearer <token>; la respuesta (generalmente JSON) se deserializa en objetos del modelo.

Ejemplos

// Ejemplo conceptual de consulta a API REST con Token JWT en JavaScript (Fetch)
async function obtenerPerfil(token) {
  const respuesta = await fetch("https://api.ejemplo.com/v1/perfil", {
    method: "GET",
    headers: {
      "Authorization": `Bearer ${token}`,
      "Content-Type": "application/json"
    }
  });
  if (!respuesta.ok) throw new Error("Error de autenticación o red");
  return await respuesta.json();
}

Gestión de Sensores

Definición

Los sensores móviles son componentes de hardware (o virtuales basados en software) integrados en smartphones y tabletas que detectan cambios físicos en el entorno o en el movimiento del dispositivo y los transforman en señales digitales interpretables por la aplicación.

Tipos de Sensores en Dispositivos Móviles

Sensores de Movimiento

Miden fuerzas de aceleración y rotación en tres ejes (X, Y, Z): Acelerómetro, Giroscopio, sensor de gravedad y podómetro (contador de pasos).

Sensores de Posición

Determinan la ubicación física y orientación espacial: Magnetómetro (brújula digital), Sensor de proximidad (apaga pantalla en llamadas) y receptor GNSS/GPS.

Sensores Ambientales

Miden parámetros del entorno externo: Sensor de luz ambiental (brillo automático), Barómetro (presión atmosférica/altitud), termómetro e higrómetro.

Proceso de Gestión de Sensores

  1. Habilitación: Se obtiene una instancia del gestor de sensores del sistema (ej. SensorManager en Android o CMMotionManager en iOS), se verifica si el sensor existe y se registra un oyente (listener) definiendo la frecuencia de muestreo.
  2. Obtención: El sistema operativo dispara eventos periódicos cuando cambian los valores del sensor, entregando un arreglo de mediciones (ej. aceleración en m/s² en ejes X, Y, Z) junto con una marca de tiempo y nivel de precisión.
  3. Procesamiento de información: Se aplican filtros (como filtro paso bajo para aislar la gravedad o fusión de sensores) para eliminar ruido, ejecutar la lógica de negocio y finalmente desregistrar el sensor en onPause() para ahorrar batería.

Uso de Recursos Multimedia

Definición

Los recursos multimedia en aplicaciones móviles comprenden la integración, reproducción, captura y manipulación de contenido visual y auditivo para enriquecer la experiencia del usuario y facilitar la comunicación de información.

Tipos de Recursos Multimedia

  • Imágenes: Gráficos rasterizados (PNG, JPEG, WebP) para fotografías y texturas, y gráficos vectoriales (SVG, VectorDrawable) que escalan sin pérdida de calidad en distintas densidades de pantalla.
  • Audio: Efectos de sonido cortos, música de fondo y notas de voz en formatos como MP3, AAC, OGG o WAV.
  • Video: Secuencias audiovisuales locales o en streaming adaptativo (HLS, DASH) codificadas en H.264/AVC, H.265/HEVC o VP9 dentro de contenedores MP4/WebM.
  • Animaciones y elementos visuales dinámicos: Transiciones de interfaz, animaciones vectoriales basadas en JSON (Lottie), GIF animados, gráficos 2D/3D (OpenGL ES, Vulkan, Metal).

Estructura de Proyectos donde se Almacenan

  • Android (Proyecto Gradle):
    • res/drawable/ y res/mipmap/: Imágenes, íconos y gráficos vectoriales organizados por densidad (mdpi, hdpi, xhdpi, xxhdpi).
    • res/raw/: Archivos de audio o video sin compresión adicional accesibles mediante ID de recurso.
    • res/anim/ y res/animator/: Definiciones XML de animaciones.
    • assets/: Archivos multimedia arbitrarios (como animaciones Lottie o fuentes) leídos por ruta directa.
  • iOS (Xcode): Assets.xcassets para catálogos de imágenes adaptativas y el Main Bundle para audio/video.

Componentes de Software en el Uso de Multimedia

  • Reproductores y motores: MediaPlayer y ExoPlayer (Media3) en Android; AVPlayer y AVAudioPlayer en iOS.
  • Captura de medios: APIs de cámara y micrófono como CameraX / Camera2, MediaRecorder (Android) y AVFoundation (iOS).
  • Librerías de carga y caché de imágenes: Glide, Coil o Picasso para decodificación asíncrona y gestión eficiente de memoria RAM.

Servicios y Notificaciones

Definición

Los servicios son componentes de aplicación capaces de ejecutar operaciones de larga duración sin proporcionar una interfaz de usuario directa, mientras que las notificaciones son mensajes visuales o sonoros mostrados fuera de la interfaz de la app para informar al usuario sobre eventos relevantes o acciones pendientes.

Tareas en Segundo Plano en Aplicaciones Móviles

Son procesos que se ejecutan cuando la aplicación no está visible en primer plano (por ejemplo: sincronización de datos, descarga de archivos, rastreo de ubicación o reproducción de música). Los sistemas móviles modernos imponen restricciones estrictas (como Doze Mode en Android) para optimizar el consumo de batería, exigiendo el uso de planificadores inteligentes.

Tratamiento de Notificaciones en Aplicaciones Móviles

  • Notificaciones Locales: Programadas directamente por la aplicación dentro del dispositivo (ej. recordatorios, alarmas).
  • Notificaciones Push (Remotas): Enviadas desde un servidor externo hacia el dispositivo mediante servicios de mensajería del sistema operativo, incluso si la app está cerrada.
  • Canales y Prioridades: Agrupación temática (en Android 8.0+) que permite al usuario configurar sonido, vibración e importancia por categoría, además de soportar acciones rápidas y respuestas directas.

Proceso de Implementación

  • Proveedores de contenido (Content Providers): Gestionan el acceso estructurado a un repositorio central de datos y permiten compartir información de forma segura entre distintas aplicaciones mediante URIs y permisos explícitos (ej. acceder a contactos o galería).
  • Tareas en segundo plano: Se implementan mediante WorkManager (Android) o BackgroundTasks (iOS) para tareas diferibles garantizadas, o mediante Foreground Services (con notificación persistente visible) para procesos inmediatos como navegación GPS.
  • Notificaciones: Se solicita permiso explícito al usuario (POST_NOTIFICATIONS), se registra el canal de notificación, se construye el objeto mediante NotificationCompat.Builder (o UNUserNotificationCenter) y se despacha con un identificador único.

Servicios de Cómputo en la Nube Aplicables

  • Notificaciones Push: Firebase Cloud Messaging (FCM) y Apple Push Notification service (APNs).
  • Backend como Servicio (BaaS): Firebase, Supabase y AWS Amplify (autenticación, bases de datos en tiempo real, almacenamiento de archivos y funciones serverless).
  • Infraestructura y APIs escalables: Google Cloud Platform, Amazon Web Services (AWS) y Microsoft Azure.

Librerías y Toolkits para Desarrollo Móvil

¿Qué es una Librería y qué es un Toolkit?

Librería (Biblioteca)

Es una colección de código preescrito (clases, funciones y métodos) diseñada para resolver un problema específico (ej. peticiones HTTP, manejo de fechas o carga de imágenes). El desarrollador mantiene el control del flujo de la aplicación e invoca la librería cuando la necesita.

Toolkit (Kit de Herramientas / UI Toolkit)

Es un conjunto integral de herramientas, componentes de interfaz de usuario, compiladores, depuradores y APIs que proporcionan la base completa para construir, diseñar y compilar toda una aplicación dentro de un ecosistema.

Librerías de Funciones Especializadas

  • Redes y consumo de APIs: Retrofit, OkHttp, Ktor, Alamofire, Axios.
  • Serialización JSON: Gson, Moshi, Kotlinx.serialization.
  • Inyección de dependencias: Dagger Hilt, Koin.
  • Procesamiento de imágenes y gráficos: Glide, Coil, Lottie, MPAndroidChart.

Diferenciar Toolkits Aplicables a la Programación Móvil

Toolkit Enfoque / Plataforma Lenguaje Principal Características Diferenciales
Jetpack Compose Nativo Android Kotlin UI declarativa moderna de Google; elimina archivos XML y acelera el desarrollo nativo.
SwiftUI Nativo iOS / Apple Swift Framework declarativo de Apple para crear interfaces nativas en iPhone, iPad y Apple Watch.
Flutter Multiplataforma (Compilado) Dart Renderiza sus propios widgets mediante motor gráfico propio (Impeller/Skia) a 60/120 fps.
React Native Multiplataforma (Nativo-puente) JavaScript / TypeScript Utiliza componentes nativos reales de cada plataforma y ecosistema web React.
.NET MAUI Multiplataforma C# / XAML Evolución de Xamarin.Forms respaldada por Microsoft para Android, iOS, Windows y macOS.

Depuración y Seguridad

¿Qué es la Depuración y la Seguridad?

Depuración (Debugging)

Es el proceso sistemático de identificar, analizar, aislar y corregir errores (bugs), fugas de memoria y cuellos de botella de rendimiento en el código fuente antes y después del despliegue de la aplicación.

Seguridad Móvil

Es el conjunto de prácticas, controles criptográficos y arquitecturas destinadas a proteger la integridad de la app, la confidencialidad de los datos del usuario y las comunicaciones frente a ingeniería inversa, interceptación y accesos no autorizados.

Herramientas de Depuración en el Entorno de Desarrollo Móvil

  • Breakpoints y Step-by-Step Debugger: Puntos de interrupción en Android Studio o Xcode que pausan la ejecución para inspeccionar variables, pila de llamadas (Call Stack) y evaluar expresiones en vivo.
  • Logcat / Consola de sistema: Visor de registros en tiempo real filtrable por nivel de severidad (Verbose, Debug, Info, Warning, Error) y etiqueta.
  • Android Profiler / Xcode Instruments: Herramientas visuales para monitorear uso de CPU, asignación de memoria RAM, tráfico de red y consumo energético.
  • Layout Inspector / View Debugger: Inspección jerárquica en 3D de los componentes visuales renderizados en pantalla.
  • Network Inspector / Proxies (Charles, Proxyman): Análisis de peticiones y respuestas HTTP/HTTPS para validar encabezados y cargas útiles.

Prácticas Clave de Seguridad Móvil

  • Ofuscación de código: Uso de R8 / ProGuard para renombrar clases y métodos dificultando la ingeniería inversa del APK/AAB.
  • Cifrado en tránsito y reposo: Uso obligatorio de TLS/HTTPS, Certificate Pinning y almacenamiento de llaves en hardware seguro (Android Keystore / Secure Enclave).
  • Principio de mínimo privilegio: Solicitar únicamente los permisos estrictamente indispensables en tiempo de ejecución.
